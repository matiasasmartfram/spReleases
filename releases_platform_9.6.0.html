Refactorización integral y optimización del sistema de tokens para MercadoPago (SmartCloud).

Información de Despliegue

Fecha de Despliegue: 15/04/2026

Resumen General de la Versión

A lo largo de toda la iteración de fixes de la Task 221 para la versión 9.6.0, el foco principal giró en torno de optimizar abruptamente la latencia e infraestructura general de comunicación frente a la plataforma base central "SmartCloud". Antes, la API sufría repetitivamente de sobrecargas forzadas pidiendo en formato HTTP directo vía axios los tokens por absolutamente cada pedido o webhook detectado en MercadoPago. Ahora, el sistema deposita el activo de autenticación recibido en un nuevo caché Mongo Local por user_id (TokenMercadoPago), acortando el flujo intermedio y sólo solicitando delegaciones de llaves estrictamente ante ausencias y logrando mitigar comportamientos tóxicos no previstos en el originador.

Análisis Técnico Detallado

api/src/models/tokenMercadoPago.js (Creado)

Nueva Entidad de Persistencia

La intención principal es crear una nueva colección temporal en MongoDB (TokenMercadoPago) para persistir de modo local los tokens traídos desde SmartCloud por cada user_id. El impacto de sumar esta "caché" evita la alta penalización de red de peticionar constantemente las credenciales.

Código DESPUÉS
const mongoose = require('mongoose');
const { Schema } = mongoose;
const tokenMercadoPagoSchema = new Schema({
    tokenMercadoPago: { type: Object }
}, {
    timestamps: true
});
module.exports = mongoose.model('TokenMercadoPago', tokenMercadoPagoSchema);

Conclusión: Se establece el modelo de almacenamiento físico y estructura base en MongoDB que habilita la reutilización de credenciales vigentes pre-obtenidas.

api/src/utils/tokensCloud.js (Creado y modificado)

Abstracción de Lógica de Integración

Se extrajo abstractamente toda la lógica de obtención e intercepción del token externo de MP llevándola a una nueva utilidad tokensCloud.js. Durante la validación, la funcionalidad integró:

  • Detecciones robustas explicitando fallos cuando el endpoint devuelve "No Content (204)".
  • Aseguramiento sintáctico obligando a que la respuesta HTTP sea rigurosamente un objeto validando typeof tokenMercadoPagoCloud !== 'object'.
  • Salvaguarda del nuevo token recibido en MongoDB a través del nuevo modelo tokenMercadoPagoModel.create(...).
  • Correcciones menores de sintaxis en el grabado de variables en objetos de Error Log (user_id: user_id).
Código DESPUÉS
import Log from '../utils/log';
import Token from '../utils/token';
import axios from 'axios';
import tokenMercadoPagoModel from '../models/tokenMercadoPago';

class tokensCloud {
  static async getTokenMercadoPagoCloud(user_id, tenantId, url = null) {
    try {   
      const tokenAPICloud = await Token.getToken();  
      const headersToken = {
        headers: {
          'Authorization': `Bearer ${tokenAPICloud}`,
          'TraceKey': '1234',
          'TenantId': tenantId
        }
      }
      let urlTokenMercadoPagoCloud = url ? `${url}${user_id}` : `https://xxx/api/v1/IntegratedEntity/GetAccessTokenMPByUser/${user_id}`;
      let tokenMercadoPagoCloud;
      try {
        tokenMercadoPagoCloud = await axios.get(urlTokenMercadoPagoCloud, headersToken);
        // ...
      } catch (error) {
        // ...
        throw error;
      }      
      
      tokenMercadoPagoCloud = tokenMercadoPagoCloud.data;
      
      if (!tokenMercadoPagoCloud || typeof tokenMercadoPagoCloud !== 'object') {
        Log.saveError(null, { /*...*/ });
        throw new Error('Invalid token response from cloud');
      }
      
      tokenMercadoPagoCloud.user_id = user_id;
      tokenMercadoPagoCloud.new = true;
      await tokenMercadoPagoModel.create({tokenMercadoPago: tokenMercadoPagoCloud})
      return tokenMercadoPagoCloud;
    } catch (err) {  
      Log.saveError(err,{message: 'Error fetching token from Cloud', user_id: user_id, tenantId: tenantId, url: url});
      return null;
    }
  }
}
module.exports = tokensCloud;

Conclusión: A través de tokensCloud.js, el servicio adopta ahora su propio "Worker" funcional responsable de arbitrar los tokens transaccionales, descongestionando los archivos maestros.

Correcciones de Scope y Desestructuración (Hotfixes)

Se erradicaron errores vitales de declaración impidiendo el flujo exitoso general de Mercado Pago (Scope/Reference Errors y Destructuring inválido):

  • Scope/Missing declarations: Se declaran explícitamente let orderfail y let ordersSaved.
  • Crash por Destructuring: Se corrigió el acceso a user_id. El elemento original intentaba sacar una propiedad de sí mismo asumiendo un sub-objeto, forzando un undefined o ReferenceError.

/* ... */

/* ... */
