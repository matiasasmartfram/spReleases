Notas de Release: Platform 10.2.0

Este release introduce la arquitectura multi-país para la integración de UberEats (habilitando Uber Eats Argentina junto a Chile de manera simultánea), y optimiza el enrutamiento JWT global del middleware Express y la limpieza de imports en MercadoPago.

Resumen General de la Versión

La versión 10.2.0 marca un hito en la arquitectura de Platform al implementar el soporte multi-país nativo en la integración de UberEats. Esto permite que el Concentrador y la Plataforma manejen de forma independiente y paralela las credenciales OAuth en formato JSON, la renovación automática de tokens y el direccionamiento geográfico de pedidos de Uber Eats en Argentina y Chile bajo un único proceso backend. Adicionalmente, se flexibiliza el enrutamiento de excepciones JWT para admitir subrutas dinámicas parametrizadas de webhooks y se eliminan modelos de datos obsoletos no utilizados en MercadoPago para depurar el código fuente de producción.

Modificaciones Identificadas

1. Exclusiones JWT dinámicas para webhooks UberEats

Se reemplaza la exclusión rígida de la ruta del webhook de UberEats por una expresión regular flexible /\/api\/uberEats\/uber-notification\/?.*/. Esta modificación permite que cualquier solicitud HTTP POST dirigida a la ruta base o a sub-rutas dinámicas que identifiquen un país (por ejemplo, /api/uberEats/uber-notification/Argentina o /api/uberEats/uber-notification/Chile) queden automáticamente exceptuadas de la validación del middleware JWT global de Express, previniendo rechazos de autenticación en la comunicación con Uber.

api/src/platforms/management/platform/uberEats.js

Modificaciones Identificadas

1. Estructura de almacenamiento de credenciales multi-país (Commit 69ff072)

Se cambia la variable this.tokenUber de un string plano a un objeto vacío {} en el constructor de UberEats. Además, las propiedades clientSecret y clientId ahora se parsean como JSON, permitiendo que almacenen y representen un mapa dinámico indexado por país (por ejemplo, { "Argentina": "id1", "Chile": "id2" }).

2. Login OAuth automatizado en bucle por región (Commit 69ff072)

Se implementa una iteración en uberLogin que recorre cada par país-clientId en el objeto parseado, e invoca al método de autenticación asíncrono loginCountryUber(country, clientId).

3. Autenticación OAuth segmentada y logging enriquecido (Commit 69ff072)

El método loginCountryUber realiza la solicitud a la API de Uber de forma independiente usando las credenciales del país correspondiente y almacena el token resultante en this.tokenUber[country]. Si ocurre un fallo, el logger registra detalladamente el país y el id del cliente del error.

4. Operaciones parametrizadas por país y metadata estructurada (Commit 69ff072)

Todas las solicitudes HTTP salientes de pick-up, cancelaciones y status resuelven el token como this.tokenUber[order.country]. Además, al guardar los logs se estructuran los campos de extraData con el país de la sucursal de origen (currentBranch.address.country) y la fecha de pick-up ISO.

5. URL de Login productiva para UberEats (Commit 827665a)

Se comenta de forma definitiva la variable de sandbox en urlLogin y se apunta directamente al endpoint de autenticación productivo de Uber (https://auth.uber.com/oauth/v2/token).

Conclusión General

Este release de Platform introduce una re-arquitectura estratégica en la integración con UberEats al habilitar la coexistencia multi-país (Argentina y Chile). A través del parsing de credenciales JSON, autenticación paralela en bucle, enrutamiento dinámico exceptuado por expresiones regulares y mapeo de tokens indexados por región, el backend se vuelve capaz de procesar pedidos concurrentes de múltiples marcas y países desde un mismo contenedor Node.js. Adicionalmente, el robustecimiento general con control de nulos, try-catch resiliente y re-lanzamiento obligatorio de errores en webhooks garantiza la continuidad de las operaciones críticas y la observabilidad de incidentes en producción.
