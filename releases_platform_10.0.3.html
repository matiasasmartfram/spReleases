Resumen General de la Versión

Este release de Platform corrige la validación y el formateo de datos externos de UberEats (external_data) al mapear los detalles de los modificadores de la orden. Además, optimiza el enrutamiento de webhooks para la recepción de notificaciones de UberEats agregando soporte para un endpoint genérico y un fallback dinámico del token de autenticación cuando el país especificado en los parámetros no posee una clave configurada.

Conclusión del Archivo

La corrección del error de escritura restablece la correcta validación de identificadores de ítems adicionales (modificadores) en los pedidos de UberEats. Esto asegura que los identificadores de integración (como el SKU) sean parseados e incorporados al pedido final sin interrupciones.

api/src/controllers/uberEats.js

Modificaciones Identificadas

1. Mecanismo de Fallback para Autenticación de la API UberEats

Se incorpora un comportamiento de contingencia para la obtención del token Bearer necesario al consultar la API de UberEats. Si las credenciales para el país recibido en el parámetro de la petición no existen en el objeto tokenUber del cliente, la aplicación ahora realiza un fallback automático utilizando las credenciales asignadas a "Chile".

Código ANTES


              let urlAvailability = `${platform._platform.credentials.data.baseUrl}/v1/delivery/order/${orderId}?expand=carts,payment,deliveries`;

              const headersConfig = {
                headers: {
                  'Authorization': `Bearer ${platform.tokenUber[req.params.country]}`,  
                }
              };   
              let uberOrder = await axios.get(urlAvailability, headersConfig);

Código DESPUÉS


              let urlAvailability = `${platform._platform.credentials.data.baseUrl}/v1/delivery/order/${orderId}?expand=carts,payment,deliveries`;
                         
              const headersConfig = {
                headers: {
                  'Authorization': `Bearer ${platform.tokenUber[req.params.country] || platform.tokenUber['Chile']}`,
                }
              };
              let uberOrder = await axios.get(urlAvailability, headersConfig);

Conclusión del Archivo

La introducción de la contingencia en la autenticación protege la comunicación outbound contra caídas accidentales causadas por la falta de mapeo del país en la solicitud del webhook, garantizando la continuidad en la descarga de los detalles de la orden.

Este endpoint genérico complementa la ruta preexistente parametrizada por país, y se documenta adecuadamente utilizando anotaciones de Swagger para facilitar la integración externa.

Conclusión General

Este release de Platform estabiliza de forma significativa la integración con la plataforma UberEats mediante la corrección de fallas de ejecución e incremento de la resiliencia en la ingesta de órdenes. Por un lado, la solución de errores sintácticos y la provisión de un fallback por defecto en el validador de SKUs garantizan que los modificadores y datos externos de los productos sean interpretados de manera consistente sin disparar excepciones no controladas. Por otro lado, la flexibilización de la autenticación mediante un fallback a las credenciales de "Chile" y la exposición del endpoint genérico documentado con Swagger robustecen la API frente a variaciones en las solicitudes entrantes desde la plataforma de delivery. Estos cambios, en conjunto, minimizan el riesgo de pérdida de pedidos y optimizan el diagnóstico de fallas a través de un mejor registro de trazas de error.
