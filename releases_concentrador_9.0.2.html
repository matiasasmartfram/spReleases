Corrección del filtro Cloud/NoCloud en el Backoffice y ajuste de configuración de desarrollo.

Resumen General de la Versión

Este release corrige dos problemas operacionales. El primero afectaba al filtro Cloud/NoCloud del Backoffice, que no funcionaba correctamente por un error de sintaxis en la consulta MongoDB. El segundo corrige la configuración de nodemon en package.json para que el hot-reload apunte al directorio de código fuente correcto durante el desarrollo. Adicionalmente se incorpora manejo de errores en la función de búsqueda de noticias.

Análisis Técnico Detallado

api/package.json

Modificaciones Identificadas

1. Corrección de Ruta de Monitoreo en Desarrollo (nodemon)

Se corrige la configuración del script start en package.json. El parámetro --watch de nodemon estaba apuntando a dist/ (directorio compilado) cuando debería apuntar a src/ (directorio fuente). Esto causaba que los cambios en el código fuente no se reflejaran automáticamente en modo desarrollo. Con esta corrección, cualquier cambio en los archivos de src/ dispara una recompilación automática mediante Babel.

Código ANTES

    "start": " nodemon --inspect=127.0.0.1:9229  src/index.js --watch dist --exec babel-node",

Código DESPUÉS

    "start": " nodemon --inspect=127.0.0.1:9229  src/index.js --watch src --exec babel-node",

Conclusión del Archivo

La configuración del desarrollo es ahora correcta. El comando npm run start monitorea cambios en src/ en lugar de esperar a que aparezcan cambios en dist/, mejorando la experiencia de desarrollo con hot-reload verdadero.

api/src/controllers/news.js

Modificaciones Identificadas

1. Corrección de Operador MongoDB en Filtro Cloud/NoCloud

Se corrige un error en la consulta MongoDB que filtra noticias por estado cloud. El código original utilizaba $cloud (con signo de dólar) como nombre de campo, cuando en realidad $cloud no es un operador MongoDB válido — el prefijo $ se usa exclusivamente para operadores como $in, $gte, etc. El campo correcto es simplemente cloud. Como resultado, el filtro cloud/nocloud producía resultados inconsistentes al seleccionar "NoCloud" en el Backoffice.

2. Adición de Manejo de Errores Integral (try-catch)

Se envuelve toda la función search() en un bloque try-catch. Esto captura cualquier error no previsto y retorna una respuesta HTTP 400 con un mensaje de error, en lugar de dejar que la aplicación falle o lance excepciones no controladas.

Conclusión del Archivo

El controlador news.js tiene ahora un filtro cloud/nocloud funcional y protección contra errores no previstos. La corrección de $cloud a cloud restablece el comportamiento esperado del filtro en el Backoffice. El try-catch agrega resiliencia a search(), uno de los endpoints más utilizados del Concentrador.

Conclusión General

Este release corrige dos problemas operacionales. El error de sintaxis MongoDB ($cloud en lugar de cloud) invalidaba el filtro Cloud/NoCloud en el Backoffice, impidiendo que los usuarios distinguieran entre sucursales cloud e instalaciones on-premise. La corrección en package.json asegura que nodemon monitoree src/ en lugar de dist/, habilitando el hot-reload correcto durante el desarrollo. La adición del try-catch en search() hace que el endpoint retorne un error controlado en lugar de fallar sin respuesta.
