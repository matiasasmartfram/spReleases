Resumen General de la Versión

Este release introduce la automatización de la sincronización de estado (Check-in/Check-out) mediante cron jobs para UberEats y MercadoPago. Además, corrige un fallo crítico en la consulta de estado de UberEats (getStatus()) posterior a un cierre forzado, donde la ejecución de la verificación para sucursales en Argentina producía un error de referencia indefinido, y rectifica el método HTTP para la actualización de disponibilidad en UberEats.

1. Planificación horaria y cron job para sincronización de UberEats

Se planifican ejecuciones horarias fijas en cronPeya() a través de la constante UberEatsTimes (12:16 y 16:46 hora local). 2. Implementación de sendStatusUberEats()

Se crea esta función para recorrer todas las sucursales del país especificado que posean activa la integración con UberEats. Divide las sucursales en dos listas: branchesToClose (locales con la bandera alreadyClosedUber: true) y branchesToOpen (locales con alreadyClosedUber: false). A través de Promise.allSettled, ejecuta llamadas HTTP POST a la API de UberEats (update-store-status) por cada branchReference para actualizar a OFFLINE u ONLINE según corresponda. Finalmente, registra el resultado global en openClosedLogModel bajo el Identificador "Uber" y el tipo "Special".

    const closePromises = branchesToClose.map(async (branch) => {
        const branchId = branch.branchId;
        const branchData = { branchId, results: [] };
        const branchReference = branch.platforms.find(pm => pm.platform == uberId).branchReference;
        const branchReferences = Array.isArray(branchReference) ? branchReference : [branchReference];

        await Promise.allSettled(branchReferences.map(async (store_id) => {
        let body = {
          "is_offline_until": mañana.toISOString(),
          "status": "OFFLINE",

            branchReference: store_id,
            type: "Closed",
            result: false
          });

            branch: {
                branchReferenceId: store_id,
                branchId: branchId
            },
            request: {
                url: urlAvailability,
                method: 'POST',
                body: body,
                header: headersConfig
            },
            response: {
                status: error?.response?.status,

            branchReference: store_id,
            type: "Open",
            result: false
          });

            message: \`Branch OpenClose Error: Uber sendStatusUberEats OPEN \${branch.branchId}\`, 
            action: 'sendStatusUberEats',
            platformId: 4,
            operation: 'OPEN',
            branch: {
                branchReferenceId: store_id,
                branchId: branch.branchId

                url: urlAvailability,

                header: headersConfig

          });

        platformId: 4,
        type: "Special"

      message: \`Branch OpenClose Error: Uber checkOfflinePOSuber GENERAL\`, 
      action: 'checkOfflinePOSuber',
      platformId: 4,
      operation: 'GENERAL'

Modificaciones Identificadas

1. Corrección del flujo condicional de estado ONLINE en getStatus() para Uber

La función getStatus() posee una validación de estado específica para UberEats en sucursales argentinas. Se detectó que el bloque para resolver sucursales en Argentina evaluaba status === "ONLINE", pero por un error de alineación y anidación la condición quedaba fuera del bloque principal, ejecutando un throw Error("Estado no existe") inesperado cuando el local estaba online. Se reorganiza y agrupa la lógica para que evalúe y retorne correctamente closed: false.

2. Corrección del método HTTP para cierre en closeBranchUber()

El método HTTP utilizado en closeBranchUber() para enviar el cambio de estado OFFLINE a la API de UberEats era incorrecto (axios.put). Uber requiere POST en ese endpoint. Se corrige y actualiza a axios.post.

Conclusión General

Este release automatiza los flujos de Check-In/Check-Out periódicos para UberEats y MercadoPago agregando crons específicos parametrizados por huso horario UTC. Además, corrige un bug crítico de regresión surgido tras los merges multi-país de la 9.1.0/9.2.0: la consulta de estado de Uber en Argentina (getStatus()) interrumpía la ejecución lanzando un error cuando el local estaba ONLINE. Finalmente, se corrige la llamada de API de cierre en Uber cambiando el verbo HTTP erróneo de PUT a POST.
