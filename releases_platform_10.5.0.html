Notas de Release: Platform 10.5.0

Este release incorpora soporte para el flujo de entrega de última milla de Tucán (PediGrido): un nuevo endpoint permite confirmar la entrega de un pedido al operador logístico, marcando la orden como entregada en la base de datos y notificando al API de PediGrido. Como complemento, el flujo de delivery automático de Rapiboy queda condicionado para no ejecutarse cuando el pedido tiene a Tucán como socio logístico, y los campos de estado y socio de entrega se propagan por el sistema.

Resumen General de la Versión

Este release añade la integración con el servicio de última milla Tucán (PediGrido) para el flujo de entrega de pedidos. Se introduce un nuevo endpoint para que el punto de venta (POS) confirme la entrega de un pedido a Tucán, lo que a su vez actualiza el estado de la orden en la base de datos local y notifica a la API externa de PediGrido. Adicionalmente, se previene que la automatización de entregas de Rapiboy interfiera con los pedidos de Tucán y se extienden los modelos de datos para transportar los nuevos campos de estado de entrega y socio logístico.

Análisis Técnico Detallado

api/src/controllers/thirdParty.js

Modificaciones Identificadas

1. Nuevo endpoint `deliveredOrder` para confirmación de entrega Tucán

Se agrega el handler `deliveredOrder` que recibe la confirmación de entrega de un pedido de última milla. El handler verifica que el pedido exista en MongoDB, que su `deliveryPartner` sea `tucan_ultimamilla`, marca la `news` correspondiente con `orderDelivered: true` y llama al endpoint `EntregarPedido` de la API de PediGrido (URL y token provenientes de las credenciales de la plataforma). Cualquier fallo en la llamada externa queda registrado en `logError` sin interrumpir la respuesta al cliente.

2. Guardia de orden ya entregada en `cancelOrder`

Antes de procesar la cancelación, se consulta la `news` asociada al pedido. Si `orderDelivered` está en `true`, se rechaza la cancelación con un `400`. Esto previene que un pedido ya entregado por Tucán pueda ser cancelado posteriormente.

3. Corrección de indentación en el bloque SML de `cancelOrder`

El bloque `try/catch` del flujo de canje SML estaba desalineado respecto al `if(fullOrder.order.user.contieneCanje)`. El cambio corrige la indentación para que refleje correctamente la estructura de control.

4. Incorporación de `newsModel` y `axios` a las dependencias del controlador

Se agregan los imports de `newsModel` (para la guardia de `orderDelivered` y la actualización en `deliveredOrder`) y `axios` (para la llamada a PediGrido), ambos necesarios para el nuevo flujo.

5. Exportación de `deliveredOrder`

El nuevo handler se agrega al `module.exports` del controlador para que la capa de rutas pueda referenciarlo.

Conclusión General

Este release integra el flujo de última milla de Tucán (PediGrido) en Platform. El cambio central es un nuevo endpoint que permite al POS confirmar la entrega de un pedido: al recibirlo, Platform marca la news como entregada en MongoDB y notifica al API de PediGrido. El flujo existente de Rapiboy queda condicionado para no duplicar la notificación cuando el pedido tiene a Tucán como socio logístico.

Para soportar este flujo, se extienden tres capas del sistema: el schema de news agrega el campo orderDelivered, el interface de terceros propaga deliveryPartner durante la normalización de la orden, y la estrategia de tipos de news proyecta ambos campos en el resultado para que estén disponibles en el POS. El conjunto no altera el flujo de órdenes de otras plataformas (PedidosYa, UberEats, Rappi, MercadoPago).
