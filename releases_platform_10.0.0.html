Resumen General de la Versión

Este release marca un hito importante en la infraestructura de SmartPedidos. Se ha realizado una migración completa de los SDKs de AWS a la versión 3 (v3), se ha actualizado el runtime a Node 20 y se ha optimizado el entorno de contenedores para una gestión más robusta de certificados SSL.

api/Dockerfile

Modificaciones Identificadas

1. Actualización de Runtime y Gestión de Certificados

Se actualiza la imagen base de Node 14 a Node 20.20-alpine. Además, se añade soporte nativo para certificados CA de Sectigo y se configura la variable de entorno NODE_EXTRA_CA_CERTS para asegurar que las conexiones HTTPS utilicen el bundle del sistema, evitando errores de handshake.

Código ANTES

WORKDIR /usr/src/app
COPY package.json .
RUN npm install
COPY . .
RUN npm run build

#
# Build stage 2.
#

WORKDIR /usr/src/app
COPY package.json .
RUN npm install --only=production
COPY --from=BASE /usr/src/app/dist ./dist
ENTRYPOINT ["npm", "run"]
CMD ["serve"]

Código DESPUÉS

FROM node:20.20-alpine AS base
WORKDIR /usr/src/app

COPY . .

#
# Build stage 2.

api/src/platforms/provider/aws.js

Modificaciones Identificadas

1. Refactorización de Clientes AWS (SSM y SQS)

Se implementa el patrón de comandos (Command Pattern) de AWS SDK v3. Se reemplazan las llamadas encadenadas .promise() por clientes instanciados en el constructor y el uso de await client.send(command).

Código ANTES

import AWS from 'aws-sdk';

class Aws {
  constructor() {
    AWS.config.update({
      region: config.AWS.REGION,
      accessKeyId: config.AWS.accessKeyId,
      secretAccessKey:  config.AWS.secretAccessKey
    });
  }

  retriveKey({ key = requiredParam('key') }) {
    const ssm = new AWS.SSM({ credentials: null });
    return ssm
      .getParameters({ Names: [key] })
      .promise()
      .then((res) => res.Parameters.pop())
      .then((param) => param.Value);
  }

  async pushNewToQueue(newOrder) {
    const sqs = new AWS.SQS({ region: config.AWS.SQS.REGION, credentials: null });
    const params = { MessageBody: JSON.stringify(newOrder), ... };
    return sqs.sendMessage(params).promise();
  }
}

Código DESPUÉS

import { SQSClient, SendMessageCommand, GetQueueAttributesCommand } from '@aws-sdk/client-sqs';
import { SSMClient, GetParametersCommand } from '@aws-sdk/client-ssm';

class Aws {
  constructor() {
    this.sqsClient = new SQSClient({ region: config.AWS.SQS.REGION });
    this.ssmClient = new SSMClient({ region: config.AWS.REGION });
  }

  async retriveKey({ key = requiredParam('key') }) {
    const command = new GetParametersCommand({ Names: [key] });
    const res = await this.ssmClient.send(command);
    const param = res.Parameters.pop();
    return param.Value;
  }

  async pushNewToQueue(newOrder) {
    const params = {
      MessageBody: JSON.stringify(newOrder),
      MessageGroupId: newOrder._id.toString(),
      MessageDeduplicationId: deduplicationIdGen(newOrder._id.toString(), newOrder.branchId.toString())
    };
    const command = new SendMessageCommand(params);
    return this.sqsClient.send(command);
  }
}

deploy-staging.sh y deploy-prod.sh

Modificaciones Identificadas

1. Automatización de Despliegue vía CLI

Se introducen scripts de Bash para reemplazar las pipelines de CI/CD eliminadas. Estos scripts realizan validaciones de rama, building multitag de Docker y la actualización de la tarea en ECS.

Código (Fragmento de deploy-prod.sh)

#!/bin/bash
set -e

export REGION=us-east-1
export BUILD_TAG=$(cat api/version)
export PROJ_IMG=smartfran/platform-service
export ECR_REPOSITORY=382381053403.dkr.ecr.us-east-2.amazonaws.com

# Validamos si estamos en la rama develop
if [ "$CURRENT_BRANCH" != "develop" ]; then
      echo "No estas en develop!! (rama actual: $CURRENT_BRANCH)"
      ...
fi

# Build and TAG
docker build \
    -t ${ECR_REPOSITORY}/${PROJ_IMG}:${BUILD_TAG} \
    -t ${ECR_REPOSITORY}/${PROJ_IMG}:${BUILD_TAG}-${REV_PARSE} \
    ./api/

# Deploy
envsubst < container-definitions-prd.json > ecs-container-definitions.json
aws ecs register-task-definition --cli-input-json file://ecs-container-definitions.json --region ${REGION}
aws ecs update-service --cluster smartfran-pedidos-production --service platform-service-production-service --force-new-deployment

Conclusión General

El Release 10.0.0 constituye una redefinición estratégica de la infraestructura de SmartPedidos Platform, marcando el fin de un ciclo de deuda técnica y el inicio de una arquitectura modernizada y sostenible. La transición a Node 20, AWS SDK v3 y la gestión robusta de certificados SSL asienta una base tecnológica robusta capaz de soportar la escalabilidad y las exigencias del ecosistema logístico de SmartPedidos para los próximos años.
