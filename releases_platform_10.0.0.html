Resumen del Release

Este release marca un hito importante en la infraestructura de SmartPedidos. Se ha realizado una migración completa de los SDKs de AWS a la versión 3 (v3), se ha actualizado el runtime a Node 20 y se ha optimizado el entorno de contenedores para una gestión más robusta de certificados SSL.

Modificaciones Técnicas Clave

1. Actualización de Runtime y Gestión de Certificados

Se actualiza la imagen base de Node 14 a Node 20.20-alpine. Además, se añade soporte nativo para certificados CA de Sectigo y se configura la variable de entorno NODE_EXTRA_CA_CERTS para asegurar que las conexiones HTTPS utilicen el bundle del sistema.

Archivo: api/Dockerfile
Código ANTES
FROM node:14-alpine AS BASE
WORKDIR /usr/src/app
COPY package.json .
RUN npm install
COPY . .
RUN npm run build

WORKDIR /usr/src/app
COPY package.json .
RUN npm install --only=production
COPY --from=BASE /usr/src/app/dist ./dist
ENTRYPOINT ["npm", "run"]
CMD ["serve"]

FROM node:20.20-alpine AS base
WORKDIR /usr/src/app
COPY package.json .
RUN npm install
COPY . .
RUN npm run build

#
# Build stage 2.

2. Migración a AWS SDK v3

Se migra de la librería monolítica aws-sdk (v2) a clientes modulares de la versión 3. Se implementa el patrón de comandos (Command Pattern) para SQS y SSM.

Archivo: api/src/platforms/provider/aws.js
Código ANTES
import AWS from 'aws-sdk';

class Aws {
  constructor() {
    AWS.config.update({
      region: config.AWS.REGION,
      accessKeyId: config.AWS.accessKeyId,
      secretAccessKey:  config.AWS.secretAccessKey
    });
  }

  retriveKey({ key = requiredParam('key') }) {
    const ssm = new AWS.SSM({ credentials: null });
    return ssm
      .getParameters({ Names: [key] })
      .promise()
      .then((res) => res.Parameters.pop())
      .then((param) => param.Value);
  }

  async pushNewToQueue(newOrder) {
    const sqs = new AWS.SQS({ region: config.AWS.SQS.REGION, credentials: null });
    const params = { MessageBody: JSON.stringify(newOrder), ... };
    return sqs.sendMessage(params).promise();
  }
}
Código DESPUÉS
import { SQSClient, SendMessageCommand, GetQueueAttributesCommand } from '@aws-sdk/client-sqs';
import { SSMClient, GetParametersCommand } from '@aws-sdk/client-ssm';

class Aws {
  constructor() {
    this.sqsClient = new SQSClient({ region: config.AWS.SQS.REGION });
    this.ssmClient = new SSMClient({ region: config.AWS.REGION });
  }

  async retriveKey({ key = requiredParam('key') }) {
    const command = new GetParametersCommand({ Names: [key] });
    const res = await this.ssmClient.send(command);
    const param = res.Parameters.pop();
    return param.Value;
  }

  async pushNewToQueue(newOrder) {
    const params = {
      MessageBody: JSON.stringify(newOrder),
      MessageGroupId: newOrder._id.toString(),
      MessageDeduplicationId: deduplicationIdGen(newOrder._id.toString(), newOrder.branchId.toString())
    };
    const command = new SendMessageCommand(params);
    return this.sqsClient.send(command);
  }
}

5. Automatización de Despliegue vía CLI

Se introducen scripts de Bash (deploy-staging.sh y deploy-prod.sh) para reemplazar las pipelines de CI/CD anteriores. Estos scripts centralizan el flujo de validación, compilación y actualización de servicios en AWS ECS.

Archivo: deploy-prod.sh
Código de Automatización
# Login ECR
$(aws ecr get-login --profile ${PROFILE} --no-include-email --region us-east-2)

# Build multitag
docker build -t ${ECR_REPOSITORY}/${PROJ_IMG}:${BUILD_TAG} ./api/

# Actualización ECS
envsubst < container-definitions-prd.json > ecs-container-definitions.json
aws ecs update-service --cluster smartfran-pedidos-production --service ... --force-new-deployment

Conclusión General

El Release 10.0.0 constituye una redefinición estratégica de la infraestructura de SmartPedidos Platform. Se han consolidado tres pilares fundamentales:

  • Modernización: Transición a Node 20 y AWS SDK v3 para un rendimiento optimizado y carga modular.
  • Seguridad: Gestión robusta de certificados CA Sectigo para handshakes SSL garantizados.
  • Control Operativo: Implementación de flujos de despliegue manual vía CLI para mayor visibilidad y auditoría.

Este salto de versión asienta una base tecnológica robusta capaz de soportar la escalabilidad y las exigencias del ecosistema logístico de SmartPedidos para los próximos años.
