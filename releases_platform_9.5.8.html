Resumen General de la Versión

Se ha realizado una mejora importante en la forma en que el sistema de Platform procesa las cantidades de los productos y sus componentes adicionales originados en aplicaciones de delivery (PedidosYa y Rappi). Estos ajustes resuelven un problema donde no se estaban calculando adecuadamente las cantidades de los ingredientes extra cuando se ordenaba más de una unidad de un producto compuesto, y además, garantiza que los artículos de algunas promociones en Rappi incluyan siempre la cantidad correcta. En definitiva, estos cambios aseguran que los pedidos entren al sistema con cantidades exactas de todos sus componentes, mejorando la gestión de inventario, la facturación y minimizando la posibilidad de discrepancias operativas.

Análisis Técnico Detallado

📄 api/src/platforms/interfaces/pedidosYa.js

Impacto: Corrección en el cálculo multiplicativo de cantidades para sub-opciones en el mapeo de PedidosYa.

Código ANTES

              itemDescription: option.name,
              price: option.price,
              discount: 0,
              quantity: option.quantity,
// ...
                itemDescription: element.option.name,
                price: parseFloat(element.option.price) || 0,
                discount: 0,
                quantity: element.option.quantity
// ...
              itemDescription: element.option.name,
              price: 0,
              discount: 0,
              quantity: element.option.quantity

Código DESPUÉS

              itemDescription: option.name,
              price: option.price,
              discount: 0,
              quantity: option.quantity * ( detail.quantity),
// ...
                itemDescription: element.option.name,
                price: parseFloat(element.option.price) || 0,
                discount: 0,
                quantity: element.option.quantity * ( detail.quantity)
// ...
              itemDescription: element.option.name,
              price: 0,
              discount: 0,
              quantity: element.option.quantity * ( detail.quantity)

Análisis

En el método detailsMapperParseOther responsable del mapeo de opciones, existía un defecto lógico: si el cliente seleccionaba un multiplicador en el artículo principal (detail.quantity), las opciones o componentes de ese artículo no se multiplicaban por dicho valor. Se añadió * (detail.quantity) para que las cantidades de las opciones reflejen adecuadamente el total solicitado a nivel del pedido.

📄 api/src/platforms/interfaces/rappi.js

Impacto: Inclusión de cantidades para productos promocionales agrupados.

Código ANTES

                  detDetails.promo = 1;
                  detDetails.groupId = numberOfPromotions;
                  detDetails.description = product.name;
                  detDetails.sku = validationSKU(product.sku)

Código DESPUÉS

                  detDetails.promo = 1;
                  detDetails.groupId = numberOfPromotions;
                  detDetails.description = product.name;
                  detDetails.count = product.quantity; // Se añade el conteo
                  detDetails.sku = validationSKU(product.sku)

Análisis

Al procesar productos atados a promociones en Rappi (con groupId), se estaba omitiendo el registro de la cantidad del producto (count). Se añadió la asignación detDetails.count = product.quantity; para asegurar que los procesos de downstream puedan acceder al volumen exacto de cada artículo promocional.
