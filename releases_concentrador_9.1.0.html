Notas de Release: Concentrador 9.1.0

Integración de UberEats Argentina: autenticación multi-país, segmentación de tokens por país y paso a producción del endpoint OAuth.

Información de Despliegue

Versión: 9.1.0

Fecha de Despliegue: 12/05/2026

Resumen General de la Versión

Este release habilita la operación de sucursales argentinas en UberEats. Hasta ahora, el sistema solo gestionaba credenciales y tokens de UberEats para Chile. Con este cambio, cada país utiliza sus propias credenciales de acceso y su propio token, lo que permite abrir, cerrar y consultar el estado de sucursales de Argentina y Chile de forma independiente. También se activa el entorno real de UberEats, reemplazando la configuración de pruebas que estaba en uso.

Commit: 9011dec9 — Merge pull request #37 from smartit-ar/uberTokenArgentina

api/src/controllers/branch.js

Modificaciones Identificadas

1. Conversión de credenciales y token de UberEats a estructura por país

Las variables tokenUber, uberClientId y uberClientSecret pasan de ser strings simples a objetos con clave por país. Las credenciales se leen desde configuración como JSON, lo que permite definir valores distintos para Argentina y Chile sin cambios en el código. El token resultante de la autenticación se almacena como tokenUber["Argentina"] o tokenUber["Chile"] según corresponda.

2. Refactorización de uberLogin() con nueva función loginCountryUber()

La función uberLogin() deja de realizar la autenticación directamente y pasa a iterar sobre los países disponibles en uberClientId, delegando cada autenticación a loginCountryUber(country, clientId). Esta nueva función maneja el ciclo de login de forma independiente por país, almacena el token correspondiente y registra el error con contexto de país y clientId si falla.

3. Segmentación de headers de autorización en checkOfflinePOSuber() y sendOpen()

El header Authorization único basado en tokenUber se reemplaza por dos configuraciones: headersConfigAr (con tokenUber["Argentina"]) y headersConfigCl (con tokenUber["Chile"]). Las llamadas a axios.post() para apertura y cierre automático ahora seleccionan el header según branch.address.country.

4. Segmentación por país en getStatus()

La consulta de estado a la API de UberEats en getStatus() pasa de usar un header único a usar headersConfigAr o headersConfigCl según el país de la sucursal, con bloques if separados para Argentina y Chile.

5. Uso de token por país en sendReject() y rejectOrdersPeya()

El rechazo de órdenes UberEats pasa a construir el header de autorización usando tokenUber[orderInfo.extraData.country] y tokenUber[reject.extraData.country] respectivamente, en lugar del token único anterior.

Conclusión del Archivo

El controlador de sucursales incorpora soporte multi-país para UberEats. La autenticación pasa de un token único compartido a un token por país, y todas las operaciones que interactúan con la API de UberEats (apertura, cierre, consulta de estado, rechazo de órdenes) seleccionan el token según el país de la sucursal. El cambio es aditivo: Argentina se agrega sin romper el flujo existente de Chile.

1. Cambio de URL de autenticación UberEats de sandbox a producción

La función loginCountryUber() apuntaba al endpoint de sandbox de UberEats (sandbox-login.uber.com). Este commit actualiza la URL al endpoint de producción (auth.uber.com), necesario para que los tokens obtenidos sean válidos en el entorno real de la plataforma.

Conclusión del Archivo

La autenticación con UberEats pasa a ejecutarse contra el endpoint de producción. Junto con el commit de soporte multi-país, este cambio completa el ciclo de integración: los tokens obtenidos son válidos para operar sucursales reales en Argentina y Chile.

Conclusión General

Este release integra UberEats Argentina al Concentrador. El cambio principal reestructura el modelo de autenticación con UberEats: de un token único compartido a un mapa de tokens por país, obtenidos con credenciales independientes configuradas como JSON. Todos los puntos de uso del token (apertura, cierre automático, consulta de estado, rechazo de órdenes) se actualizan para seleccionar el token del país correspondiente a la sucursal. Un commit adicional corrige un conflicto de merge que dejaba el bloque de Argentina sin evaluar el estado ONLINE, y el último commit mueve la autenticación al endpoint de producción de UberEats.
