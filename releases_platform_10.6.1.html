Notas de Release: Platform 10.6.1

Este release de Platform (v10.6.1) introduce correcciones en el procesamiento periódico de órdenes y en el formateador de salida del sistema de logging. Se soluciona un error de sintaxis en la expresión cron que afectaba a MercadoPago y se enriquece la salida estructurada de logs en consola (JSON) para incluir el stack trace y preservar metadatos no estructurados en colectores cloud.

Resumen General de la Versión

Este release soluciona un error de sintaxis crítica en el cron programado de MercadoPago, permitiendo la sincronización continua de órdenes, y mejora el formateador de logs estructurados en consola para preservar los stack traces y la metadata no estructurada en colectores cloud.

Análisis Técnico Detallado

api/src/controllers/mercadoPago.js

Modificaciones Identificadas

1. Corrección de expresión cron para la programación de órdenes

Se rectifica la cadena del programador cron a '*/5 * * * * *' (cada 5 segundos) reemplazando la sintaxis errónea anterior '5/ * * * * *'. Esto restaura el funcionamiento del procesador programado de órdenes pendientes de MercadoPago, el cual fallaba al arrancar.

Código ANTES

const scheduleOrders = '5/ * * * * *';  
cron.schedule(scheduleOrders, async () => await checkOrders());

Código DESPUÉS

const scheduleOrders = '*/5 * * * * *';  
cron.schedule(scheduleOrders, async () => await checkOrders());

Conclusión del Archivo

mercadoPago.js estabiliza su cron de procesamiento periódico de pedidos, permitiendo la sincronización de órdenes sin interrupciones del parser.

api/src/utils/log.js

Modificaciones Identificadas

1. Inclusión de pila de llamadas (stack trace) en salida de logs

Se agrega la propagación de error.stack como error_stack en el objeto JSON enviado a la salida estándar (process.stdout), facilitando la depuración profunda de fallos de infraestructura y lógica.

2. Persistencia de propiedades adicionales de log

Se añade el soporte para propagar el resto de los metadatos desestructurados (rest) en el objeto de log impreso por consola. Esto asegura que la metadata específica (como URLs, cabeceras o estados HTTP) no se pierda en colectores cloud de logs.

Código ANTES

    static _stdout(level, customData, error) {
        if (!LOG_STDOUT) return;
        const { message, category, branch_id, platform_id, order_id, ...rest } = customData;
        const entry = {
            timestamp:  new Date().toISOString(),
            service:    SERVICE_NAME,
            level,
            category:   category ?? undefined,
            message,
            ...(branch_id   !== undefined && { branch_id }),
            ...(platform_id !== undefined && { platform_id }),
            ...(order_id    !== undefined && { order_id }),
            ...(error?.message && { error: error.message }),
            ...(error?.code    && { error_code: error.code }),
        };
        process.stdout.write(JSON.stringify(entry) + '\n');
    }

Código DESPUÉS

    static _stdout(level, customData, error) {
        if (!LOG_STDOUT) return;
        const { message, category, branch_id, platform_id, order_id, ...rest } = customData;
        const entry = {      
            timestamp:  new Date().toISOString(),
            service:    SERVICE_NAME,
            level,
            category:   category ?? undefined,
            message,
            ...(branch_id   !== undefined && { branch_id }),
            ...(platform_id !== undefined && { platform_id }),
            ...(order_id    !== undefined && { order_id }),
            ...(error?.message && { error: error.message }),
            ...(error?.code    && { error_code: error.code }),
            ...(error?.stack   && { error_stack: error.stack }),
            ...(rest !== undefined && { rest: rest })
        };
        process.stdout.write(JSON.stringify(entry) + '\n');
    }

Conclusión del Archivo

log.js refina su formateador de salida estándar JSON, garantizando que el stack de errores y la metadata adicional viajen correctamente hacia la observabilidad en la nube.

Conclusión General

La versión 10.6.1 de Platform corrige dos puntos de fallo identificados tras los últimos releases. Primero, repara la sintaxis del cron de MercadoPago que impedía la correcta ejecución periódica del check de órdenes. Segundo, robustece la reforma de logging (Reforma LogErros) al garantizar que tanto el stack de error como los campos adicionales no estructurados se impriman en el JSON de stdout, completando la observabilidad total en los colectores de la nube.
