Resumen General de la Versión

Esta actualización mejora significativamente la comunicación con MercadoPago al introducir un sistema de almacenamiento de "llaves digitales" (tokens) que evita tener que solicitarlas a la nube en cada operación. Esto hace que acciones como abrir o cerrar una tienda, o cancelar un pedido, sean mucho más rápidas y confiables, incluso si la conexión con los servicios centrales de SmartCloud presenta intermitencias.

Análisis Técnico Detallado

api/src/controllers/branch.js

Modificaciones Identificadas

1. Implementación de Caché de Tokens de MercadoPago

Se introduce una estructura de datos Map llamada tokensCache para almacenar los tokens de acceso de MercadoPago en memoria. Esto optimiza el rendimiento del sistema al evitar consultas redundantes a la base de datos o a servicios externos en la nube para cada operación que requiera autenticación con la API de MercadoPago.

2. Centralización de Búsqueda de Tokens con searchToken

Se crea la función asincrónica searchToken que implementa una estrategia de búsqueda jerárquica: primero intenta obtener el token del caché, luego de la base de datos local y, si no existe en ninguna de las anteriores, realiza una petición a SmartCloud. Al obtenerlo, actualiza automáticamente el caché para futuras consultas.

3. Optimización de Procesos de Apertura/Cierre y Rechazo

Se refactorizan las funciones ckeckOfflinePOSmercadopago, sendReject, rejectOrdersPeya, getStatus y sendOpen. Se eliminó la lógica compleja de obtención de tokens que existía dentro de cada una de estas funciones, reemplazándola por llamadas directas a la nueva función centralizada searchToken. Esto reduce significativamente la duplicación de código y mejora la mantenibilidad.

4. Automatización de Refresco y Limpieza de Tokens

Se integran dos nuevos cron jobs: uno para obtener y cachear nuevos tokens cada minuto (getTokensNewMercadoPagoCloudBranch) y otro para eliminar tokens expirados (con menos de 24 horas de validez) cada 3 horas.

api/src/controllers/branch.js (Fixes)

Modificaciones Identificadas

1. Corrección de Mapeo en el Caché de Tokens

En la función tokensLoad, se corrigió la forma en que se guardaban los tokens en el Map. Previamente se intentaba acceder a una propiedad anidada inexistente, lo que causaba que el caché quedara vacío o con claves incorrectas. Ahora se utiliza t.user_id como clave directamente.

2. Sincronización de Llamadas a searchToken

Se identificó que la función searchToken no estaba siendo esperada con await en varios puntos críticos del controlador. Al ser una función asincrónica que puede requerir acceso a la base de datos o red, el omitir el await provocaba que se utilizara una Promesa en lugar del token real.

3. Poblado de Datos de Cadena (Chain)

Se añadió .populate("chain") en las consultas de búsqueda de sucursales. Esto es crucial ya que el sistema de tokens depende de identificar correctamente el tenantId basado en el nombre de la cadena (branch.chain.chain).

Conclusión General

El release Concentrador 8.8.0 marca un hito importante en la eficiencia de la integración con MercadoPago. La implementación del sistema híbrido de tokens (Memoria + MongoDB + Cloud) resuelve problemas críticos de latencia y saturación de API que afectaban las operaciones de apertura, cierre y rechazo de pedidos en sucursales con altos volúmenes de tráfico.

Los cambios clave incluyen:

  • Resiliencia Operativa: Gracias al almacenamiento persistente en tokenMercadoPagoModel, el sistema puede operar incluso ante interrupciones momentáneas de la comunicación con SmartCloud.
  • Eficiencia Técnica: El uso de tokensCache (Map) reduce el overhead de red y procesamiento, mejorando la velocidad de respuesta de las APIs internas.
  • Robustez: Se han corregido fallos de sincronización y tipado (omisiones de await y mapeos incorrectos) detectados durante la implementación inicial, asegurando un flujo de ejecución predecible y seguro.

En conjunto, esta actualización proporciona una base sólida y escalable para las integraciones de última milla a través de MercadoPago proximity integration.
