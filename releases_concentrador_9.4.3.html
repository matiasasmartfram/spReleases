Resumen General de la Versión

Este release introduce una traza de log inicial y registros de error detallados para el chequeo automático de diferencias horarias (UTC) de los países. Además, se replanifica la hora de ejecución del cron job a las 07:00 AM de la mañana.

Análisis Técnico Detallado

api/src/controllers/branch.js

Modificaciones Identificadas

1. **Replanificación horaria de la tarea cron de UTC**
El cron job se reconfigura para ejecutarse a las 07:00 AM (cron: `'0 7 * * *'`), en lugar de las 04:00 AM (cron: `'0 4 * * *'`).
2. **Argumentación del tipo de ejecución en cron**
Se pasa la cadena `'Scheduled'` al llamar a `checkUTC.checkUTC()` para identificar que la ejecución fue lanzada automáticamente por planificación.

Código ANTES

async function syncCheckUTC() {
  if ( process.env.NODE_ENV === 'production'){
    const schedule = '0 4 * * *';
    cron.schedule(schedule, async () => await checkUTC.checkUTC());
  }
}

Código DESPUÉS

async function syncCheckUTC() {
  if ( process.env.NODE_ENV === 'production'){
    const schedule = '0 7 * * *';
    cron.schedule(schedule, async () => await checkUTC.checkUTC('Scheduled'));
  }
}

Conclusión del Archivo

Se ajusta la hora de control del cron y se añade el identificador del tipo de ejecución.

api/src/index.js

Se añade el argumento `'Initial'` al llamado manual de verificación UTC ejecutado durante el arranque del servidor en producción.

Código ANTES

  if (process.env.NODE_ENV === 'production') await checkUTC.checkUTC()

Código DESPUÉS

  if (process.env.NODE_ENV === 'production') await checkUTC.checkUTC('Initial');

Conclusión del Archivo

Permite diferenciar el log de control gatillado durante el encendido del servidor.

api/src/utils/checkUTC.js

Modificaciones Identificadas

1. **Registro del inicio de ejecución de UTC**
El método `checkUTC` recibe ahora el parámetro `ejecution` y registra un log de inicio informativo indicando el disparador (`Initial` o `Scheduled`).
2. **Registro de errores por país en consulta de TimezoneDB**
Se añaden llamadas detalladas a `Log.saveError` dentro del catch de la llamada a la API de cada país (Argentina, Perú, Uruguay, Paraguay, Chile) para facilitar el diagnóstico si falla la comunicación con TimezoneDB.

Conclusión del Archivo

Se añaden logs de diagnóstico y trazabilidad al proceso de sincronización horaria de sucursales.

Conclusión General

Este release introduce mayor observabilidad en el proceso de verificación UTC. Añade logs para registrar el arranque manual (`Initial`) y la ejecución programada diaria (`Scheduled`), junto con registros detallados si falla la llamada a la API de TimezoneDB para cualquier país. Adicionalmente, el cron job se traslada a las 07:00 AM.
