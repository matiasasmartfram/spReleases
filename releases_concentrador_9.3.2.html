Resumen General de la Versión

Este release introduce correcciones de segmentación geográfica en la sincronización periódica (Check-In/Check-Out) de UberEats. Se corrige la obtención y selección de credenciales/tokens para Argentina y Chile filtrando las sucursales por país desde la consulta de base de datos, y se simplifica la construcción de los headers de autorización utilizando la clave de país de forma dinámica en vez de condicionales estáticos. Por último, se estandarizan las propiedades identificadoras y el tipo de log de auditoría generados por el cron de UberEats.

Modificaciones Identificadas

1. Filtrado geográfico de sucursales en la consulta de base de datos

En sendStatusUberEats(), se limita la consulta añadiendo la condición 'address.country': country en las llamadas de Mongoose para traer únicamente los locales correspondientes a la región procesada por el cron.

2. Simplificación dinámica del header de autorización

Se elimina la segmentación condicional estática por país en el Axios de disponibilidad. Ahora se genera una única variable de autorización configurada dinámicamente según el país en proceso: tokenUber[country].

3. Estandarización de auditoría y tipo en log de cron de UberEats

Se modifican los campos de creación de log de disponibilidad en openClosedLogModel. La propiedad Ident pasa del valor genérico "Uber" al parametrizado UberEatsCron {country}, facilitando la auditoría de ejecución por región. El campo type se reconfigura de "Special" a "CRON".

4. Ajuste en reporte de errores

Se corrigen los mensajes de captura de excepciones generales en sendStatusUberEats() para referenciar correctamente la acción activa en lugar de checkOfflinePOSuber.

Conclusión General

Este release optimiza la sincronización de disponibilidad de UberEats al limitar las consultas de base de datos a sucursales que correspondan estrictamente al país procesado en la iteración cron actual. A partir de esto, se simplifica el envío de las cabeceras HTTP recuperando el token a través del identificador de país dinámico. Se reestructuran asimismo los logs de auditoría en base de datos para registrar el Check-In/Check-Out bajo la denominación UberEatsCron {country} y el tipo CRON.
