Resumen General de la Versión

Este commit solitario forma parte de manera contundente de la estrategia implementada en la versión interior de Caché Local. Proviene como el remate indispensable a la "Task 222", permitiendo que las credenciales caducadas o alteradas por SmartCloud que desencadenaban un estancado "401 Unauthorized" disparen un Retry/Refresh Request y logren que las llamadas al webhook funcionen sin intervención manual. Para que este bucle fluya libre de errores, las librerías secundarias empezaron a manejar la lógica de sobreescritura (Upsert) contra la base de datos interna y frenaron el registro innecesario en logs para los falsos estados 204. Esto asegura transacciones robustas y robustece su tolerancia en fallos concurrentes a futuro.

Mecanismo de Reintento y Tolerancia a Errores (Retry Fall-back)

El objetivo principal de esta modificación es implementar tolerancia a fallos por expiración de caché local o revocación ("Retry Mechanism"). Se incorpora la bandera tokenCached = true la cual indica si la credencial fue extraída de MongoDB local en lugar de ser pedida en vivo. Si al intentar ejecutar axios.put(...) en el webhook de MercadoPago la plataforma devuelve un HTTP 401 Unauthorized, el entorno atrapa el error y autodispara un "refresh": forzando un nuevo token de tokensCloud, esquivando el caché, sobreescribiendo los validadores y re-intentando la llamada axios.put(...).

Mantenimiento de Colección y Sanitización del Logger

Sanitización del Logger (Falso Positivo): Se insertó validación lógica if (tokenMercadoPagoCloud?.response?.status === 204) mitigando el bug semántico de salvar errores al log asumiéndolos inherentemente.
Transición de create a findOneAndUpdate (Upsert): Cambia la manipulación de MongoDB a un formato de escritura upsert: true garantizando la reescritura silenciosa de credenciales oxidadas (evitando crasheos por llaves duplicadas `user_id`); pieza fundamental para poder reciclar credenciales en el mecanismo Retry recién expuesto.
