Resumen General de la Versión

Este release marca un punto de inflexión estructural en el Concentrador. Se realiza la migración masiva a Node 20, la transición al AWS SDK v3, la actualización del middleware de seguridad express-jwt, y el desmantelamiento total de la infraestructura de CI/CD legacy en favor de un modelo de orquestación manual via CLI con multitagging de imágenes.

Análisis Técnico Detallado

api/Dockerfile

Modificaciones Identificadas

1. Upgrade de Runtime a Node 20

Se actualiza la imagen base a node:20.20-alpine, garantizando compatibilidad con las últimas parches de seguridad y mejoras de rendimiento del motor V8. Se mantiene el esquema de build multi-etapa para mantener la imagen de producción ligera.

Código ANTES

FROM node:14-alpine AS BASE
WORKDIR /usr/src/app
COPY package.json .
RUN npm install
COPY . .
RUN npm run build

FROM node:14-alpine
WORKDIR /usr/src/app
COPY package.json .
RUN npm install --only=production
COPY --from=BASE /usr/src/app/dist ./dist

Código DESPUÉS

FROM node:20.20-alpine AS base
WORKDIR /usr/src/app
COPY package.json .
RUN npm install
COPY . .
RUN npm run build

FROM node:20.20-alpine
WORKDIR /usr/src/app
COPY --from=base /usr/src/app/package*.json .
RUN npm install --only=production
COPY --from=base /usr/src/app/dist ./dist

Conclusión del Archivo

Actualización exitosa del entorno de ejecución a una versión moderna y soportada de Node.js.

api/src/app.js

Modificaciones Identificadas

1. Migración de Middleware de Seguridad (express-jwt v8)

Actualización mandatoria del middleware de seguridad. La librería cambia su forma de exportación ({ expressjwt }) e indica que requiere especificar explícitamente los algoritmos de firmado, en este caso HS256.

Código ANTES

import jwt from 'express-jwt';

app.use(jwt({ secret: settings.token.secret }).unless({ path: exceptions }));

Código DESPUÉS

import { expressjwt } from 'express-jwt';

app.use(expressjwt({ secret: settings.token.secret, algorithms: ['HS256'] }).unless({ path: exceptions }));

Conclusión del Archivo

Adaptación del middleware de autenticación a la nueva versión, mejorando la seguridad y compatibilidad.

api/src/provider/aws.js

Modificaciones Identificadas

1. Refactorización a AWS SDK v3 Command Pattern

Se elimina el uso de AWS.SQS / AWS.SSM y se adoptan los clientes modulares. El código ahora utiliza el patrón de envío de comandos (.send(new Command(...))), eliminando la necesidad de encadenar .promise().

Código ANTES (SQS Queue Creation)

    const sqs = new AWS.SQS({
      region: REGION,
      credentials: null
    });
    return sqs
      .createQueue({
        QueueName: queue,
        Attributes: attributes
      })
      .promise();

Código DESPUÉS (SQS Client Command)

    const sqs = new SQSClient({ region: REGION });
    return sqs.send(new CreateQueueCommand({
      QueueName: queue,
      Attributes: attributes
    }));

Conclusión del Archivo

Migración exitosa al patrón de comandos de AWS SDK v3, logrando un código más modular y preparado para el futuro.

Desmantelamiento de Infraestructura Legacy

Modificaciones Identificadas

1. Eliminación masiva de procesos de CI/CD y Testing Behave/Python

Se realiza un "hard cleanup" del repositorio para remover archivos de orquestación que ya no se utilizan en la nueva metodología de trabajo.

* Archivos Eliminados: .gitlab-ci.yml, Jenkinsfile, api/test/functional/*, api/seeders/*, api/sonar-project.properties

Conclusión del Archivo

Limpieza profunda de deuda técnica y archivos obsoletos, simplificando el mantenimiento del repositorio.

deploy-prod.sh y deploy-staging.sh

Modificaciones Identificadas

1. Fijación de Metodología de Despliegue CLI y Multitagging

Se introducen scripts bash que controlan el ciclo de vida del despliegue, permitiendo etiquetar las imágenes de Docker con alta granularidad (Commit, Rama, Fecha) para garantizar la trazabilidad total en ECR/ECS.

Código DESPUÉS (deploy-prod.sh - Fragmento)

# Taggeo múltiple para auditoría logística
docker build \
        -t ${ECR_REPOSITORY}/${PROJ_IMG}:${BUILD_TAG} \
        -t ${ECR_REPOSITORY}/${PROJ_IMG}:${BUILD_TAG}-${REV_PARSE} \
        -t ${ECR_REPOSITORY}/${PROJ_IMG}:${BUILD_TAG}-${TIMESTAMP} \
        -t ${ECR_REPOSITORY}/${PROJ_IMG}:${CURRENT_BRANCH} \
        ./api/

# Registro de Task Definition mediante inyección de variables
envsubst < container-definitions-prd.json > ecs-container-definitions.json
aws ecs register-task-definition --cli-input-json file://ecs-container-definitions.json

Conclusión del Archivo

Implementación de un sistema de despliegue robusto, manual y altamente auditable.

Conclusión General

El Release 9.0.0 consolida la modernización técnica del Concentrador. Se ha eliminado la fricción de herramientas de CI/CD desactualizadas y scripts de testing legacy, sustituyéndolos por un núcleo moderno en Node 20, una comunicación eficiente con AWS vía SDK v3 y un flujo de despliegue manual pero altamente auditable. La actualización de componentes críticos como Mongoose 7 y express-jwt 8 posiciona al servicio para una escala mayor y mayor seguridad operativa.
