Resumen General de la Versión

Este release introduce mejoras en el sistema de logging de errores. Permite capturar e identificar de forma robusta cualquier tipo de error (strings u objetos planos), añade la trazabilidad del `order_id` en las fallas de encolamiento de AWS SQS, y estandariza los rechazos de promesas de validación para que utilicen la clase nativa `Error` (facilitando la captura del stack trace).

Modificaciones Identificadas

1. **Estandarización de rechazo de promesas con clase Error**
En la validación de órdenes duplicadas y existencia de la sucursal, se reemplaza el retorno de promesas rechazadas con objetos planos (`reject({ error })`) por instancias nativas de la clase `Error` (`reject(new Error(error))`), asegurando la captura del stack trace.

          return reject({ error });

api/src/platforms/provider/aws.js

Modificaciones Identificadas

1. **Adición de `order_id` en logs de error de SQS**
Al fallar el procesamiento de novedades de SQS (`setNews_processing failed`), se extrae y añade el identificador del pedido (`order_id`) parseando el cuerpo del mensaje (`JSON.parse(newToSet.Body)?.id ?? 'unknown'`), mejorando la trazabilidad.

Código ANTES

                    Log.save('ERROR', error, {
                      message: '[ORDER/ERROR] setNews_processing failed consumer=parent',
                      category: 'ORDER',
                      message_group_id: newToSet?.Attributes?.MessageGroupId ?? 'unknown',
                      message_id:       newToSet?.MessageId                  ?? 'unknown'
                    });

Código DESPUÉS

                    Log.save('ERROR', error, {
                      message: '[ORDER/ERROR] setNews_processing failed consumer=parent',
                      category: 'ORDER',
                      message_group_id: newToSet?.Attributes?.MessageGroupId  ?? 'unknown',
                      message_id:       newToSet?.MessageId                   ?? 'unknown',
                      order_id:         JSON.parse(newToSet.Body)?.id         ?? 'unknown'
                    });

Modificaciones Identificadas

1. **Robustecimiento del formateo de errores en logs**
En el método auxiliar de escritura en consola `_stdout()`, se amplía el soporte del formateo del error: si es un string o un objeto sin propiedad `.message`, se realiza un `JSON.stringify` o conversión a `String`, evitando que se pierda la traza original.

Código ANTES

            ...(branch_id   !== undefined && { branch_id }),
            ...(platform_id !== undefined && { platform_id }),
            ...(order_id    !== undefined && { order_id }),
            ...(error?.message && { error: error.message }),
            ...(error?.code    && { error_code: error.code }),

Código DESPUÉS

            ...(branch_id   !== undefined && { branch_id }),
            ...(platform_id !== undefined && { platform_id }),
            ...(order_id    !== undefined && { order_id }),
            ...(error != null && { error: error?.message ?? (typeof error === 'object' ? JSON.stringify(error) : String(error)) }),
            ...(error?.code    && { error_code: error.code }),

## Conclusión General del Análisis

Este release introduce optimizaciones clave en la observabilidad de la plataforma. Evita la pérdida de trazas de error no tipadas o formateadas como string plano, añade el identificador de orden a las fallas de encolado de AWS, y migra los rechazos de promesas del gestor de plataformas a la clase nativa `Error` para garantizar el registro del stack trace original.
