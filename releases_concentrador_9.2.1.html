Resumen General de la Versión

Este release introduce una reestructuración de la URL de autenticación de UberEats para soportar parametrización según el entorno (producción, staging, testing) y soluciona un problema crítico de integración con PedidosYa cuando una sucursal retorna múltiples estados de POS. Adicionalmente, incluye control de excepciones preventivo en la autenticación general de Uber y un reintento en el registro de webhooks de Rappi.

api/src/controllers/branch.js

Modificaciones Identificadas

1. Gestión de múltiples estados de POS en integración PedidosYa

En funciones clave de control de disponibilidad como checkOfflinePOSpeya(), enviarEstadoPedidosYa(), sendOpen() y closeBranchPeya(), se detectaba y actualizaba el estado utilizando únicamente el primer elemento del arreglo retornado por PedidosYa (statuspos.data[0]). Esto provocaba comportamientos inesperados si un local retornaba más de un POS. Ahora, el código itera sobre todos los elementos dentro de statuspos.data usando un bucle for...of y realiza el PUT de disponibilidad en cada uno. Asimismo, se registra una advertencia con Log.saveError si la API devuelve más de un elemento.

2. Parametrización dinámica del endpoint de login de UberEats

La función loginCountryUber() utilizaba un string estático con la URL de producción. Se reconfigura para que utilice la variable parametrizada settings.uberParams.authUrl obtenida del archivo del entorno activo.

3. Manejo de excepciones controlado en uberLogin()

El ciclo de autenticación iterativo por país en uberLogin() se envuelve en un bloque try/catch individual para evitar que el fallo en las credenciales o conectividad de un país bloquee por completo el inicio de sesión de los países restantes.

4. Reintento de llamada de webhook Rappi en la actualización de sucursal

En la función updateOne(), si la llamada para agregar una tienda al webhook de Rappi falla, se captura el error mediante un bloque try/catch, se registra con Log.saveError y se realiza un reintento inmediato.

5. Ajuste de variables en log de error de obtención de estado de Uber

En la captura de errores de getStatus(), se corrige el objeto de metadatos de error reemplazando el valor inexistente de headersConfig por headersConfigCl y headersConfigAr.

Conclusión General

Este release introduce una corrección clave en la integración con PedidosYa: en lugar de procesar únicamente el primer elemento del estado de disponibilidad POS (statuspos.data[0]), el Concentrador ahora procesa iterativamente cada uno de los elementos devueltos para locales con múltiples terminales configurados, aplicando la disponibilidad de forma individual. Asimismo, la URL de autenticación de Uber se desacopla del código estático mediante parámetros por ambiente, y la lógica de login se aísla con bloques try/catch individuales para prevenir bloqueos en cascada. Por último, se añade un reintento robusto ante fallas de registro del webhook de Rappi en la actualización de sucursales.
