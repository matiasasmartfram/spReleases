Resumen General de la Versión

Este release corrige un problema de compatibilidad en el procesamiento de datos externos provenientes de UberEats. La plataforma puede enviar SKUs o IDs de producto en formatos variados (incluyendo valores con puntos decimales), que previamente causaban errores o comportamientos inesperados en la lógica de mapeo de productos.

api/src/platforms/interfaces/uberEats.js

Modificaciones Identificadas

1. Creación de Función de Validación de Datos Externos (SKU)

Nueva función validExternalData() que sanitiza datos externos provenientes de UberEats. La función extrae la parte anterior al punto decimal cuando existen múltiples dígitos separados por punto, lo que previene que SKUs con formato inválido (ej: "123.456.789") causen errores en parseo o asignación de IDs de producto. Esto es crítico porque UberEats puede enviar datos en diferentes formatos que, si no se validan, rompen la lógica de mapeo entre sus SKUs y los del POS.

Nueva Función de Validación
function validExternalData(externalData){
  if( externalData.includes('.')){
    return externalData.split('.')[0];
  }
  return externalData;
}

Se removieron bloques de código comentado que no eran funcionales, limpiando el procesamiento de opcionales y haciendo el flujo más legible.

Conclusión del Archivo

La interfaz UberEats de Platform ahora posee un mecanismo robusto de validación de datos externos. La introducción de validExternalData() actúa como una capa defensiva que previene que formatos inválidos de SKU (especialmente aquellos con puntos decimales o múltiples separadores) causen fallos en la asignación de IDs de producto. El cambio se aplica de manera consistente en todo el flujo de procesamiento de órdenes, tanto para promociones como para artículos regulares, asegurando que todas las rutas de código trabajen con SKUs sanitizados. Esto reduce significativamente el riesgo de órdenes rechazadas o malinterpretadas que provengan de UberEats.
