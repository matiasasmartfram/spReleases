Notas de Release: Concentrador 8.8.1

Implementación de mecanismo de auto-recuperación de tokens MercadoPago para garantizar la continuidad operativa ante expiraciones de caché.

Resumen General de la Versión

Esta actualización añade una capa de inteligencia adicional al sistema de credenciales. Ahora, si el sistema detecta que una "llave digital" (token) ha dejado de funcionar mientras se está usando, el Concentrador intentará automáticamente conseguir una nueva y re-intentar la acción sin que el usuario ni las sucursales perciban ninguna interrupción. Esto soluciona problemas esporádicos de desconexión con MercadoPago.

Modificaciones Identificadas

1. Gestión de Estado de Caché en Tokens

Se modifica la función searchToken para rastrear si el token devuelto proviene del caché (memoria o base de datos) o si es una nueva adquisición. Se añade la propiedad tokenCached al objeto de retorno, lo que permite a las funciones consumidoras saber si tienen margen para intentar un refresco en caso de error de autenticación.

2. Mecanismo de Auto-Refresco ante Errores 401

Se implementa una lógica de re-intento automático en las funciones críticas de integración con MercadoPago. Si una petición axios falla con un código de estado 401 (No autorizado) y se estaba utilizando un token cacheado, el sistema ahora intenta obtener un token fresco de la nube, lo desencripta y re-intenta la operación original.

3. Refinamiento de searchToken y Centralización del Refresco

Se añade el parámetro opcional cached a la función searchToken. Este parámetro, cuando se establece en true, fuerza a la función a ignorar los niveles de caché y realizar una petición directa a SmartCloud. Se unificaron todas las llamadas de refresco bajo esta interfaz.

}

Conclusión General

El release Concentrador 8.8.1 complementa la implementación del sistema de caché de MercadoPago introducido en la versión anterior. La principal mejora es la capacidad de auto-recuperación ante errores de autenticación.

Al detectar un error 401, el sistema ahora discrimina si el fallo pudo deberse a un token expirado en su caché interno y, de ser así, realiza un refresco transparente para el usuario y re-intenta la operación. Esta estrategia de "fallo suave" asegura una experiencia de usuario sin interrupciones y minimiza las intervenciones manuales de soporte.
