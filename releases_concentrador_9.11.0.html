Modificaciones Identificadas

1. **Recargar las Base URL desde la configuración persistida**

Se agrega `baseUrlsReload`, que consulta las plataformas configuradas y actualiza en memoria las variables de URL usadas por I+D, PedidosYa, Toque, MercadoPago, UberEats y Rappi. La URL de Rappi se interpreta como JSON, igual que el formato almacenado en sus credenciales.

`checkforcedCronHorarios` detecta `syncBaseurlConcentrador`, ejecuta la recarga y limpia junto con `forcedCronHorarios` los flags de sincronización. De esta forma, el cambio se procesa durante el ciclo existente de revisión de configuración.

api/src/controllers/thirdParty.js

Modificaciones Identificadas

1. **Agregar el endpoint de actualización de Base URL**

Se incorpora `updateBaseUrl`, que recibe el identificador de plataforma y la nueva URL, actualiza `credentials.data.baseUrl` con validación de Mongoose y devuelve la plataforma actualizada. Si no existe la plataforma, responde `404`.

2. **Solicitar la sincronización en ambos servicios**

Después de guardar el valor, el controlador marca `syncBaseurlConcentrador` y `syncBaseurlPlatform` en la configuración global. Esto comunica que el Concentrador debe recargar su estado y que Platform debe procesar su propia sincronización.

3. **Registrar errores del flujo**

Los errores del endpoint se registran con categoría `INFRA` y contexto del request antes de devolver una respuesta `400`.

Conclusión General

El release incorpora la actualización dinámica de Base URL para plataformas administradas desde Backoffice. La API persiste la nueva URL y activa flags de sincronización; el Concentrador detecta su flag durante el ciclo periódico, recarga las URLs de sus plataformas y luego limpia el estado procesado. El alcance visible del commit se centra en la Base URL y no modifica por sí mismo otras credenciales o configuraciones de plataforma.
